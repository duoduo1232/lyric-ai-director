# AI 歌词动画导演 / AI Lyric Animation Director

一个 [Folia](https://github.com/chthollyphile/folia-major) 的 [Folium](https://github.com/chthollyphile/folium-compound) 模组：让 AI 为**每一首歌**决定歌词动画长什么样。

它读取当前歌曲的歌名、歌手、专辑与歌词，从**播放器当前可用的歌词动画模式列表**里挑一个，并顺手调好这个模式的参数。每首歌的选择会被记住，再次播放直接复用，不再重复问 AI。

## 接口与密钥：模组自己填，不读宿主的

模组**不读取 Folia 自己的 AI 设置**，也不碰宿主保存的密钥。Folia 0.7.18 起把 AI 密钥加密保存（`OPENAI_API_KEY_SEALED` / `GEMINI_API_KEY_SEALED`）正是为了让本机其他代码拿不到它，本模组不去解密它。

取而代之，接口地址、模型和密钥都填在**本模组自己的设置**里（设置 → 模组 → AI 歌词动画导演）：

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 接口地址 | `https://api.openai.com/v1` | OpenAI 兼容接口。填 `https://host` 或 `https://host/v1` 都可以，会自动补 `/chat/completions` |
| 模型 | `gpt-4o-mini` | 要使用的模型名 |
| 温度 | `0.7` | 越高越随机 |
| API 密钥 | 空 | 见下方「密钥如何存放」 |

密钥怎么走：

- 密钥在设置面板里用一个 password 输入框填写，**只发给主进程**，界面层不留存、不进 `params`（那是明文 localStorage）。
- 主进程用 Electron 的 `safeStorage` 加密后存进模组自己的数据文件 `mod-data.json`（Windows DPAPI / macOS Keychain / Linux libsecret、kwallet）。文件里只有密文，明文密钥不会写盘，也不会出现在日志里。
- 每次请求时在主进程内解密使用；没有任何接口能把密钥读回界面层（只有「是否已配置 / 是否加密」的状态查询）。
- 如果系统没有可用的加密后端（某些 Linux 环境缺少 libsecret / kwallet），`safeStorage` 会报告不可用，此时密钥**只能明文存放**，设置面板会当场显示警告。除此之外所有平台都是加密存放。如果密钥是在别的机器/别的会话里加密的、本机解不开（例如直接拷贝了 `mod-data.json`），面板会显示「已保存但本机无法解密，请重新填写」，而不是假装密钥可用。
- 密钥输入框留空点「保存密钥」不会改动已保存的密钥（提示里会说明）；要删除密钥请点「清除密钥」。

密钥只用于**你自己填的这个接口**。

## 功能

- **按歌决策模式**：从播放器当前注册的歌词动画模式里选一个（含内置模式，也会包含其他模组注册的模式）。
- **同时调参**：不只是切模式，还会给出该模式的参数（例如相机强度、字体运动、转场、后期颗粒……），并按白名单与范围校验后写入播放器设置。默认**只切模式**，要连参数一起改请在设置里打开「同时应用参数」。
- **每首歌记忆**：同一首歌再次播放时直接沿用上次的模式与参数，不调用 AI（省时省钱，观感也保持一致）。想换风格可以「重新决策这首歌」。
- **提前为下一首准备**：当前歌决策完成后，若队列里的下一首还没有记忆，会趁它还没播放就先问好 AI 并写入这首歌的记忆。切歌瞬间就套用，开头几秒不再沿用上一首的动画。只写记忆，不会提前改动画面。
- **等歌词就绪再决策**：换歌后等 `lyrics.loaded` 事件再决策，不会在歌词还没到的时候用「这首歌没有歌词」去猜（确实没有歌词的曲目会在等待超时后照常决策，但**不会**把这次结果写进记忆）。
- **门控自动处理**：有些参数被开关挡着（比如后期颗粒需要先打开后期处理）。模组会成对打开所需开关，并在结果里注明「（已同时打开所需开关）」；如果 AI 明确关掉了某个开关，则标注「（被开关挡住，未生效）」而不是偷偷改动你的设置。模组自己打开的开关只作为那条参数的附注出现，不会被写成「AI 选择了这个开关」。
- **如实汇报**：结果里显示的是宿主设置里真正落下去的值。个别参数宿主会自行修正（例如「群唱」在没上传表情包时把 `custom` 改回 `builtin`，「云阶」把错序的错峰区间排成小到大），这类情况会额外标注「（宿主已按可用资源调整）」，不会报一个设置里并不存在的值。
- **不静默**：每次决策都会 toast 播报选了哪个模式；结果会连同 AI 的理由一起显示在播放器面板的「AI 导演」标签页里。
- **可恢复**：第一次改动你的动画设置之前会保存一份快照，命令面板或设置面板里的「恢复原来的设置」可以还原模式与参数。
- **无偏置**：提示词里不带「哪个模式最好/最强」的倾向，模式的选择完全交给 AI 判断歌词与气质；同时会把「这首歌上次的选择」和「最近用过的模式」交给 AI，让同一首歌稳定、不同歌尽量有差异。

## 安装

1. 下载本仓库，把模组目录（本仓库根目录）放进 `Folia 的用户数据目录/mods/`：
   - Windows：`%APPDATA%\Folia\mods\lyric-ai-director\`
   - 也就是需要 `mod.json`、`index.cjs`、`client.mjs`、`preview.jpg` 都在这个目录里。
2. 打开 Folia →「模组」面板 → 找到 **AI 歌词动画导演** → 启用并确认（未签名模组会显示「未验证」，确认一次即可）。
3. 打开「设置 → 模组 → AI 歌词动画导演」，填好**接口地址、模型、API 密钥**。没填密钥时模组不会发请求，只会在结果里提示去填。

> 提示：改动模组文件会让宿主记录的指纹失效，宿主会自动禁用它并提示「该模组的文件在你上次确认之后发生了变化」。重新在模组面板确认启用即可。

## 使用

- 打开播放器右侧面板的 **AI 导演** 标签页：
  - **让 AI 为这首歌决策**：为当前歌曲决策（若已有记忆则直接沿用）。
  - **重新决策这首歌（忽略记忆）**：忽略记忆，重新问 AI 一次并覆盖记忆。
  - 面板会显示当前模式、密钥状态、AI 的理由、上次结果、记忆与提前准备的状态。
- 命令面板里也有对应的三条命令：
  - `AI 导演：为这首歌选动画`
  - `AI 导演：重新决策这首歌`
  - `AI 导演：恢复原来的动画设置`
- 行为设置：

  | 设置 | 默认 | 说明 |
  | --- | --- | --- |
  | 换歌时自动决策 | 开 | 启用模组时若已有歌曲会决策一次，之后每首歌的歌词就绪后自动决策；已记住的歌直接复用 |
  | 记住每首歌的选择 | 开 | 同一首歌再次播放时复用上次的模式与参数，不再调用 AI |
  | 同时应用参数 | **关** | 关闭时只切换模式，保留你手动调好的参数；打开后 AI 会连同参数一起改（改动前会保存快照） |
  | 提前为下一首做准备 | 开 | 当前歌决策完成后提前为队列里的下一首决策并写入记忆 |
  | 偏好提示（可选） | 空 | 例如「安静一点」「多来点转场」，会一并交给 AI |

- 停用模组时，正在进行的请求会被中止，返回的答案不会再写入播放器设置、不会写记忆、也不会弹提示。

## 权限

- `filesystem.data`：使用 `folium.storage`，也就是模组自己的数据文件 `userData/mods-data/lyric-ai-director/mod-data.json`。里面存：
  - `aiCredential`：加密后的 API 密钥（无加密后端时为明文，面板会警告）；
  - `decisions:<歌曲键>`：每首歌的决策（校验后的模式与参数、截断到 200 字的理由、时间戳）；
  - `decisionsIndex`：记忆的最近使用顺序，用于淘汰；
  - `settingsSnapshot`：第一次改动前的动画设置快照；
  - `recentModes`：最近用过的模式（最多 8 个）。
  数据只写在本地，不会上传到任何地方。宿主对单个模组的数据文件有 1 MB 上限，模组把每首歌的记录压到很小（只存校验后的参数、理由截断），并保留最近 **300 首**，更旧的按最近使用顺序淘汰；万一仍写失败，会先清理最旧的三分之一再重试一次（重试成功后这条新记录会重新排进最近使用顺序的前面）。

本模组声明 `folia` 版本范围（`>=0.7.0 <0.8.0`），因为它使用 `folium.internals`；宿主版本不在范围内时不会加载。

## 通过 folium.internals 读写了什么

除 `folium.storage`、`folium.rpc`、`folium.ui`、`folium.log`、`folium.events`、`folium.registries` 这些公开接口外，模组通过 `folium.internals` 访问以下内容（全部为只读，除了写明「写」的那一项）：

| 读取的内容 | 用途 | 读/写 |
| --- | --- | --- |
| `stores.visualizerSettings` | 读当前模式与各模式参数；调用 `handleSetVisualizerMode(mode, { notify: false })` 与 `handleSet<模式>Tuning(patch)` 写入 | **读 + 写** |
| `stores.playback` | 读当前显示中的歌曲（含 automix 过渡时的显示歌曲）与其歌词，用于构建给 AI 的上下文 | 只读 |
| `visualizerRegistry` | 读当前可用的模式列表（发给 AI 的模式清单、校验 AI 返回的模式是否存在） | 只读 |
| `omni.getLyrics(song)` | 为**队列里的下一首**取歌词（此时这首歌还没播放，`stores.playback` 里没有它） | 只读（会向音乐源发起一次歌词请求） |
| `localStorage.getItem('player_loop_mode')` | 判断队列是否循环，从而知道队尾的下一首是谁 | 只读 |

每次访问都做了存在性检查：宿主若改了内部结构，模组会退化成一条明确的错误提示，而不是把播放器弄坏。

## 发给 AI 的内容

请求发往**你自己填的接口地址**，请求体包含：

- 歌曲信息：歌名、歌手、专辑；
- 歌词片段：最多 48 行（长歌词按间隔抽样），每行含正文、翻译、段落标记（`[Chorus]` 之类）与是否副歌；确实没有歌词时写「(这首歌没有歌词)」；
- 当前模式；
- 可选模式清单：每个模式的 id、中文名、一句话特点；
- 每个模式允许调整的参数清单（键、取值范围、默认值，以及依赖哪个开关）；
- 这首歌上次的选择（模式、参数、理由），用于保持同一首歌的观感稳定；
- 最近用过的模式列表（最多 8 个），用于让不同歌曲尽量有差异；
- 你在设置里填的「偏好提示」（如果有）。

提前为下一首做准备时，发的是**队列里下一首**的歌名、歌手、专辑与歌词（通过 `omni.getLyrics` 取得），其余相同。

不额外收集、不上传任何其他数据；不下载、不执行任何远程代码。

网络请求在主进程用 Electron 的 `net.fetch` 发出（Chromium 网络栈），因此会遵循系统的代理设置。

## 兼容性

- Folia `>= 0.7.0 < 0.8.0`（使用 `folium.internals`，需要 `folia` 版本范围声明）。在 0.7.18 上同样可用：本模组不使用宿主保存的 AI 密钥，所以宿主的密钥加密对它没有影响。
- 使用内部接口意味着 Folia 大版本更新后可能需要适配。

## 已知限制

- 需要自己填接口地址与密钥（见上文）。宿主目前没有给模组用的 AI 转发接口；如果以后提供，本模组会改为使用它，从而不再需要自持密钥。
- 「商籁」模式的 11 个倍率参数（`foliumTunables`）不在本模组的写入范围内：它们的参数存储只交给设置卡片自身，模组拿不到写入句柄。AI 改用该模式的原生参数（相机强度、字体运动、动图密度等）表达同等观感。
- 提前决策只写记忆，不改画面；如果队列里的下一首在准备完成前就被切走，这条记忆仍然有效，下次播放会命中。
- 没有歌词的曲目不会被记住（避免把一次猜测永久固定下来），但这次决策本身会照常应用。
- 记忆键取自歌曲来源 + 媒体 id（本地文件用文件 id，在线曲目用 provider + 曲目 id），因此同一首歌的不同来源不会互相覆盖。

## 开发与验证

模组是三个文件：

- `mod.json`：清单（id、版本、入口、`preview`、权限、`folia` 范围）。
- `index.cjs`：主进程。持有密钥（`safeStorage` 加密存放）、发请求（`net.fetch`）、构建提示词、解析并返回 JSON 决策；`api.lifecycle.onDeactivate` 时中止在途请求。
- `client.mjs`：界面。读歌曲/歌词、校验并写入播放器设置、每首歌记忆、快照与恢复、设置面板与播放器面板标签页、命令。

本地做过的验证（真实 AI 接口、真实 Folia 0.7.17，并对 0.7.18 的接口差异逐项核对）：

- 决策链路端到端跑通：切歌自动决策 → 应用模式与参数 → toast 播报；14 个内置模式与参数清单完整送达模型。
- 密钥密文写入 `mod-data.json`，明文不出现在数据文件、设置值或 IPC 载荷里。
- 参数按白名单与范围校验后才写入，越界值被夹到范围内，未知键被丢弃。
- 记忆命中时 AI 调用次数为 0；提前决策后切歌 0 次调用即套用。
- 连续 6 首同类抒情歌 → 6 个不同模式（不塌缩到同一个模式）。
- 每首歌的记忆键互不冲突；换歌瞬间返回的旧答案只会记到它自己的那首歌上。
- 停用模组后，在途请求返回时不再写设置、不写记忆、不弹提示。
- 写满 1 MB 上限时会先淘汰旧记录再重试。
