# AI 歌词动画导演 / AI Lyric Animation Director

一个 [Folia](https://github.com/chthollyphile/folia-major) 的 [Folium](https://github.com/chthollyphile/folium-compound) 模组：让 AI 为**每一首歌**决定歌词动画长什么样。

它复用你在「设置 → AI 主题设置」里已经配置好的 AI（OpenAI 兼容接口 / Gemini），读取当前歌曲的歌名、歌手与歌词，从 Folia 的 **14 个内置歌词动画模式**里挑一个，并顺手调好这个模式的参数。每首歌的选择会被记住，再次播放直接复用，不再重复问 AI。

![预览](preview.jpg)

## 功能

- **按歌决策模式**：从 14 个内置模式中选一个（静止、流光、心象、云阶、浮名、莫奈、群唱、倾诉、回环、镜台、时计、商籁、凝彩、绘光）。
- **同时调参**：不只是切模式，还会给出该模式的参数（例如相机强度、字体运动、转场、后期颗粒……），并**真正写入播放器设置**。
- **每首歌记忆**：同一首歌再次播放时直接沿用上次的模式与参数，不调用 AI（省时省钱，观感也保持一致）。想换风格可以「重新决策这首歌」。
- **提前为下一首准备**：当前歌决策完成后，若队列里的下一首还没有记忆，会趁它还没播放就先问好 AI 并写入这首歌的记忆。切歌瞬间就套用，开头几秒不再沿用上一首的动画。只写记忆，不会提前改动画面。
- **门控自动处理**：有些参数被开关挡着（比如后期颗粒需要先打开后期处理）。模组会成对打开所需开关，并在面板里注明「（已同时打开所需开关）」；如果 AI 明确关掉了某个开关，则标注「（被开关挡住，未生效）」而不是偷偷改动你的设置。
- **不静默**：每次决策都会 toast 播报选了哪个模式；结果会连同 AI 的理由一起显示在播放器面板的「AI 导演」标签页里。
- **无偏置**：提示词里不带「哪个模式最好/最强」的倾向，模式的选择完全交给 AI 判断歌词与气质。

## 安装

1. 下载本仓库，把模组目录（本仓库根目录）放进 `Folia 的用户数据目录/mods/`：
   - Windows：`%APPDATA%\Folia\mods\lyric-ai-director\`
   - 也就是需要 `mod.json`、`index.cjs`、`client.mjs`、`preview.jpg` 都在这个目录里。
2. 打开 Folia →「模组」面板 → 找到 **AI 歌词动画导演** → 启用并确认（未签名模组会显示「未验证」，确认一次即可）。
3. 确认「设置 → AI 主题设置」里已经填好 AI（接口地址、密钥、模型）。模组直接复用这套配置，不需要另填密钥。

> 提示：改动模组文件会让宿主记录的指纹失效，宿主会自动禁用它并提示「该模组的文件在你上次确认之后发生了变化」。重新在模组面板确认启用即可。

## 使用

- 打开播放器右侧面板的 **AI 导演** 标签页：
  - **让 AI 为这首歌决策**：为当前歌曲决策（若已有记忆则直接沿用）。
  - **重新决策这首歌（忽略记忆）**：忽略记忆，重新问 AI 一次并覆盖记忆。
  - 面板会显示当前模式、AI 的理由、上次结果、记忆与提前准备的状态。
- 命令面板里也有对应的两条命令：
  - `AI 导演：为这首歌选动画`
  - `AI 导演：重新决策这首歌`
- 设置项（设置 → 模组 → AI 歌词动画导演）：
  | 设置 | 默认 | 说明 |
  | --- | --- | --- |
  | 换歌时自动决策 | 开 | 启用模组时若已有歌曲会立即决策一次，之后每首歌开始约 2 秒后自动决策；已记住的歌直接复用 |
  | 记住每首歌的选择 | 开 | 同一首歌再次播放时复用上次的模式与参数，不再调用 AI |
  | 同时应用参数 | 开 | 关闭时只切换模式，保留你手动调好的参数 |
  | 提前为下一首做准备 | 开 | 当前歌决策完成后提前为队列里的下一首决策并写入记忆 |
  | 偏好提示（可选） | 空 | 例如「安静一点」「多来点转场」，会一并交给 AI |

## 权限

- `filesystem.data`：用于 `folium.storage`，即**每首歌的记忆**（模式 + 参数）与提前为下一首准备的缓存。数据只写在本地 `userData/mods-data/lyric-ai-director/mod-data.json`（上限 1 MB），不会上传到任何地方。

`folium.internals` 用于调用宿主已有的设置写入接口（切换歌词动画模式、写入模式参数）。因此 `mod.json` 里声明了 `folia` 版本范围；宿主版本不在范围内时不会加载。

## 隐私

- 模组只把**歌名、歌手、歌词片段**以及可选的偏好提示发给**你自己在 Folia 里配置的 AI 接口**（和「AI 主题设置」用的是同一个接口与密钥），不额外收集、不上传任何数据。
- 不下载、不执行任何远程代码。
- API 密钥只在 Folia 的主进程里读取，不会进入界面层，也不会被记录到日志。

## 兼容性

- Folia `>= 0.7.0 < 0.8.0`（使用 `folium.internals`，需要 `folia` 版本范围声明）。
- 使用内部接口意味着 Folia 大版本更新后可能需要适配。

## 已知限制

- 决策走的是 Folia 自身的 AI 设置（「设置 → AI 主题设置」），模型与温度也沿用那里的配置。
- 「商籁」模式的 11 个倍率参数不在本模组的写入范围内（它们常被其他模组接管），本模组不写这些键。
- 提前决策只写记忆，不改画面；如果队列里的下一首在准备完成前就被切走，这条记忆仍然有效，下次播放会命中。

## 开发与验证

模组是三个文件：`mod.json`（清单）、`index.cjs`（主进程：读配置、调宿主 AI 客户端、返回 JSON 决策）、`client.mjs`（界面：读歌曲/歌词、写设置、记忆、面板与命令）。

本地做过的验证（真实 AI、真实 Folia 0.7.17）：

- 决策链路端到端跑通：切歌自动决策 → 应用模式与参数 → toast 播报。
- 参数应用前后对比设置值，确认真的写入。
- 记忆命中时 AI 调用次数为 0（提前决策 → 切歌瞬间套用）。
- 连续多首风格不同的歌 → 模式选择分散，不塌缩到同一个模式。
- 每首歌的记忆键互不冲突（同一首歌稳定、不同歌区分）。
